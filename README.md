# CodePilotAI

## Overview

CodePilotAI is a multi-agent AI software engineering system built with LangGraph and Large Language Models (LLMs). It transforms a natural language application request into a fully generated software project through a structured planning, architecture, and implementation workflow.

Instead of relying on a single agent, CodePilotAI separates responsibilities across specialized agents that collaborate to analyze requirements, design project structure, and generate source code.

The system demonstrates how modern agentic AI workflows can be used to automate software development using planning, task decomposition, tool calling, state management, and iterative execution.

## Architecture

CodePilotAI follows a three-stage agent workflow:

```text
User Request
      │
      ▼
┌─────────────┐
│ Planner     │
└─────────────┘
      │
      ▼
    Plan
      │
      ▼
┌─────────────┐
│ Architect   │
└─────────────┘
      │
      ▼
  Task Plan
      │
      ▼
┌─────────────┐
│ Coder       │
└─────────────┘
      │
      ▼
 Generated Files
```

---

## Agent Responsibilities

### Planner Agent

The Planner Agent receives the user's request and converts it into a structured project plan.

Responsibilities:

* Understand user requirements
* Determine application scope
* Identify required features
* Define project files
* Select technology stack

Output:

```python
Plan
```

---

### Architect Agent

The Architect Agent transforms the high-level plan into implementation tasks.

Responsibilities:

* Analyze project structure
* Create implementation steps
* Define file-level responsibilities
* Establish task dependencies
* Generate development roadmap

Output:

```python
TaskPlan
```

---

### Coder Agent

The Coder Agent executes implementation tasks using tools.

Responsibilities:

* Read existing files
* Generate source code
* Modify project files
* Maintain compatibility across modules
* Progress through implementation steps

Output:

```python
Generated Application
```

## State Management

CodePilotAI uses LangGraph state passing to preserve workflow context.

### Plan

Stores the overall application specification.

```python
class Plan(BaseModel):
    name: str
    description: str
    techstack: str
    features: list[str]
    files: list[File]
```

---

### TaskPlan

Stores implementation tasks generated by the Architect Agent.

```python
class TaskPlan(BaseModel):
    implementation_steps: list[ImplementationTask]
```

---

### CoderState

Maintains progress during code generation.

```python
class CoderState(BaseModel):
    task_plan: TaskPlan
    current_step_idx: int
    current_file_content: Optional[str]
```

## Tooling System

CodePilotAI provides the Coder Agent with controlled filesystem access through tools.

### write_file

Creates or updates project files.

```python
write_file(path, content)
```

---

### read_file

Reads existing file contents.

```python
read_file(path)
```

---

### list_files

Lists project files recursively.

```python
list_files()
```

---

### get_current_directory

Returns the current project root.

```python
get_current_directory()
```

---

### run_cmd

Executes shell commands inside the project environment.

```python
run_cmd(cmd)
```

---

## Security

All file operations are restricted to the project root directory.

The system prevents:

* Directory traversal attacks
* Unauthorized file access
* Writing outside the project workspace

This is enforced through:

```python
safe_path_for_project()
```
